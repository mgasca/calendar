Architecture

A personal calendar: a .NET 10 minimal API and a React single-page app shipped in one container, backed by PostgreSQL, with Google sign-in for allow-listed people. The API serves events, tasks and day/week agendas; the web app shows day, week, task and overdue-triage views. Significant decisions of any kind are recorded as ADRs (any decision records) in docs/decisions and published on the documentation site.

The source is the FINOS CALM 1.3 model calendar.architecture.json (chosen in ADR-0039). calm validate --strict checks it against the CALM schema in just lint, and the documentation build checks that every ADR, story, node and relationship it names exists. Every diagram on these pages is generated from the model; the table beneath each one lists the same elements.

Elements

ElementTypeOwnershipDescription
Calendar useractorPersonA person whose verified Google email is on the allow-list. Uses the web app in a browser to see today and the week, add events and tasks, tick tasks off and triage overdue tasks.
Maintainer / operatoractorPersonThe repository owner who merges pull requests, deploys infrastructure with the infra tool, initialises secrets and roles, runs database migrations and approves production deployments.
Calendar systemsystemBuilt in this repositoryThe whole product: web app, API, generated client, contract, database, migrator and documentation site, all developed in the single repository mgasca/calendar.
Google Identity (OpenID Connect)systemExternal service we only useExternal identity provider. The API runs the OpenID Connect authorization-code flow against it; the browser is redirected to Google to sign in and back to the API callback with a code.
GitHub Actions (CI/CD)serviceHosting and tooling we configureWorkflows in .github/workflows: CI (a Changes job that decides from the changed paths which jobs a pull request or merge group needs; backend, frontend, docs site, tooling, container image + smoke test, cancelling a pull request’s superseded runs, ‘CI result’), CodeQL, dependency review, Infrastructure preview (Bicep what-if), Azure OIDC check, Database migration (manual, per environment, OIDC login) and Publish ADR site (trusted workflow_run publisher for production and PR previews).
GitHub PagessystemHosting and tooling we configureStatic hosting for the documentation site. A gh-pages state branch retains production at the root and previews under pr-preview/; only the trusted publish job (github-pages environment) has deploy permissions and publications are serialized.
Azure resource group (per environment)systemHosting and tooling we configureOne resource group per environment (staging, production) in UK South, deployed with Bicep (infra/main.bicep): monitoring, foundation (registry, vaults, identity, role assignments), database and app modules. Resource groups alone are not a security boundary: identities and role assignments are scoped per environment too.

Flows

  • Google sign-in: A signed-out person opens a deep link, signs in with Google, and comes back to the page they asked for with a…
  • View today’s agenda: The Today view shows everything for the browser’s local day in one place
  • Add an event: From the day page the person adds a timed or all-day event in a modal dialog
  • Tick a task off (optimistic): Ticking a task in any agenda or list updates the view immediately, calls the idempotent complete/reopen endpoint, rolls…
  • Triage all overdue tasks: From ‘View all N overdue’ the person pages through every open overdue task and applies a bulk action
  • Apply database migrations to an environment: The operator dispatches the Database migration workflow for staging or production
  • Publish the decision log: Merging to main
