0020 · Restructure agent guidance: a short root AGENTS.md, nested area files, a skill and hooks

Status: implemented · Date: 2026-11-04 · Issue #216 · PR #220 · PR #221 · PR #222 · PR #223 · PR #226 · PR #229 · PR #233 · PR #236 · PR #235 · PR #240 · PR #373 · PR #377 · PR #381

ADRs: ADR-0017 · ADR-0042

Story

As a calendar maintainer, I need the shared agent guidance to be short where every session reads it, disclosed on demand where only some sessions need it, and enforced mechanically where a rule must always hold, so that agents follow it reliably and each session pays only for the guidance it uses.

Tracked in epic #216. Card PR: #220; delivery PRs #221 (skill), #222 (hooks and ADR-0042), #223 (restructure) and #226 (a review suggestion on #221 that missed its merge); close-out #229; after close-out, #233 (the session-start line names the SDK, #231) #236 (the ESLint follow-up, #228), #373 (the public-post guard reads gh api bodies, #369), #377 (it reads a source through what the command states, #374) and #381 (the guards see through prefixes and wrappers, #376).

Background

AGENTS.md is imported into CLAUDE.md and read by every agent session. It grew one lesson at a time: PR #12 created it, #64 and #70 added the performance lessons, #122 and #123 the analyzer traps, #129 the story workflow, and the seven PRs of 0018 the transcript insights. On 2026-11-04 it was 148 lines and about 4,250 words. Every session pays for all of it, although the backend query lessons, the frontend render lessons, the issue-handover protocol and the file-based-tool formatting procedure each matter in a minority of sessions.

Several passages are rules that must always hold: never git checkout -- or git restore over an unstaged fix (the failure in #189), never run the shared just db recipes from a worktree without meaning to (the shared Compose defaults recorded by 0018), never hand-edit the generated contract files, never publish absolute machine paths or private session handles. Instruction text is a guideline that an agent may judge inapplicable; Claude Code’s own guidance says such rules belong in hooks.

Facts checked on 2026-11-04, before delivery, which shaped the design:

  • The repo had no hooks and no .claude/settings.json. Four skills existed (adr-draft, run-calendar, story-draft, tech-doc-review); adr-draft and story-draft referred to AGENTS.md sections by name.
  • Claude Code loads a nested CLAUDE.md lazily when it reads or edits a file under that directory, and @imports resolve relative to the importing file. Codex and Cursor read nested AGENTS.md natively. Hooks match on tool name; a deny or ask decision blocks or prompts, and additional context informs; shared hooks live in a git-tracked .claude/settings.json.
  • ADR-0017 makes every repo tool a .NET 10 file-based app under tools/<name>/, tested by just tools test. A cached dotnet run of tools/tool-versions took 0.21–0.26 s (first run 4.5 s), fast enough for a hook on every Bash or Edit call.

This story extends 0018, which made the guidance complete; this one makes it effective. The planned review of the drafting skills (0009) stays independent: this story only repointed two references in those skills.

Agreed scope

  • Short root: AGENTS.md keeps only what every session needs (overview, commands, architecture invariants, the story and issue workflow, working on several changes, testing principles, the redaction rule), at most 90 lines and 1,500 words, with a pointer to the nested files, the skills and the hooks.
  • Nested area files: backend/AGENTS.md and frontend/AGENTS.md hold the backend and frontend practices and testing notes. Each has a two-line CLAUDE.md shim that imports it, so Claude Code loads it when a file under that directory is touched and other agents read the same text natively. Each stays under 200 lines and opens by saying that the root file still applies.
  • Tooling procedures in tools/README.md: the ADR-0017 layout, tool_dirs inclusion and test discovery, the #:include SDK minimum, the scratch-project formatting procedure and the lock-file notes move there. No new skill for them: the procedure is rare and people read it too.
  • issue-handover skill: the “Public GitHub posts and optional issue handovers” section becomes .claude/skills/issue-handover/SKILL.md, loaded only when the user asks for that mode or one of its behaviours. The general redaction rule stays in the root.
  • Hooks as an ADR-0017 tool: tools/agent-hooks/ is run by Claude Code from a git-tracked .claude/settings.json. Guards that protect work or the public record deny (git restore/git checkout -- over unstaged changes, gh posts carrying machine paths or session handles, edits of generated files). The shared-database guard asks, because the user may want the shared database. The rest informs: C# lines over 140 characters after an edit, a stale contract when the agent stops, and a session-start line that warms the build cache and names the runtime. Each handler carries an if filter, so unrelated commands and edits start no process.
  • Rules survive the move: every hooked rule keeps a one-line statement in the root marked (hook), so agents without hooks still see it. The decision is recorded in ADR-0042, accepted in the hooks PR.
  • Delivery as an epic: one child issue and one PR per deliverable (#217 skill, #218 hooks and ADR, #219 restructure), as 0018 did.

Not in this story

  • Changes to what any rule requires. Wording, placement and enforcement changed; a rule that turns out to be wrong gets its own issue.
  • Lint rules for guidance that is really a code rule, such as new QueryClient() outside createQueryClient or new Intl.DateTimeFormat outside dayTime.ts. Follow-up #228.
  • A guard for bare git stash: dropped in review on #222, because it is a harness rule rather than repository guidance.
  • The issue-sweep and issue-closeout skills proposed in #168, and the content review of adr-draft and story-draft (0009).
  • Hooks for agents other than Claude Code. Their rules stay in prose.

Dependencies

Story 0019 (the justfile modules) ran in parallel. Its card (PR #214) merged before the hooks PR; its delivery (PR #227) merged after this story was delivered. #227 moved tool_dirs into tools/mod.just and renamed just tooling to just tools test, which still discovers tools/agent-hooks/tests (criterion 5). It also taught the shared-database guard the module forms just db up and just db::up, and renamed the recipes throughout this card.

Acceptance criteria

  1. Given the restructure PR, when the files are measured, then the root AGENTS.md is at most 90 lines and 1,500 words, and every instruction file (AGENTS.md, backend/AGENTS.md, frontend/AGENTS.md) is under 200 lines. Measured with wc -lw on #223’s head and again on main at 6b32bc2f: AGENTS.md 51 lines / 1,367 words (148 / 4,249 before the story), backend/AGENTS.md 56 / 829, frontend/AGENTS.md 47 / 872. On main at d2ee13f1, after story 0019 rewrote the recipe names, they are 51 / 1,459, 56 / 843 and 47 / 901: still within the limits, with 41 words to spare in the root. No check enforces these budgets: nothing fails if the root grows again.
  2. Given the old AGENTS.md, when it is compared with the new files, then every rule, command and path appears in exactly one new place, or the PR description lists it as removed because a folder README or skill already states it. The rule-preservation table in #223’s description maps every old passage to its new place or gives the reason for removing it; #221’s description does the same for the handover section. Reviewed by hand; no test compares the old and new files.
  3. Given a rule enforced by a hook, when the root AGENTS.md is read, then the rule is still stated in one line marked (hook). AGENTS.md marks four rules on five lines: generated files and the stale contract (Commands), the shared database (Commands and “Working on several changes at once”), git checkout --/git restore over an unstaged fix (Testing principles) and private details in posts (Public GitHub posts). The S103 line-length report, which only informs, is stated in backend/AGENTS.md (analyzer traps). Checked by reading; no test.
  4. Given backend/CLAUDE.md and frontend/CLAUDE.md, when they are read, then each holds only one comment and the @AGENTS.md import. backend/CLAUDE.md and frontend/CLAUDE.md each hold one HTML comment and @AGENTS.md. Checked by reading; no test.
  5. Given the hooks PR, when just tools test runs, then its output lists tools/agent-hooks/tests/agent-hooks.tests.cs and the whitespace check on tools. On 2026-11-04, just tooling (as the recipe was named before story 0019) on main content (6b32bc2f; this card changes no tool) printed dotnet run tools/agent-hooks/tests/agent-hooks.tests.cs with Total: 63, Errors: 0, Failed: 0, then dotnet format whitespace tools, and exited 0. shellcheck was not installed locally and was skipped; CI runs it.
  6. Given a hook decision branch (deny, ask, inform, pass, loop guard, malformed input), when the tests run, then a test feeds that branch sample input and asserts the exit code and output. At the process boundary, HookRunnerTests covers each branch: deny (Pre_bash_deny_is_pretooluse_json_with_exit_0, Pre_edit_denies_generated_files_and_passes_sources), ask and pass (Pre_bash_ask_and_pass), inform (Post_edit_reports_long_lines_as_context, Warm_names_the_sdk_and_the_runtime), loop guard (Stop_blocks_once_then_respects_stop_hook_active) and malformed input (Malformed_json_and_unknown_subcommands_exit_2, Missing_tool_input_passes_with_a_stderr_note). Each rule’s cases are in its guard’s tests: Discarding_unstaged_changes_is_denied, Restore_after_cd_probes_the_path_relative_to_the_new_directory, Public_posts_with_private_details_are_denied, Body_file_contents_are_scanned_and_its_path_is_not, Shared_database_from_a_linked_worktree_asks and their pass counterparts in BashGuardTests; Generated_files_are_denied and Source_files_pass; LineLengthCheckTests; ContractCheckTests; ShellCommandTests; and, since #233, the session-start SDK lookup in DotnetSdkTests. Not covered: the runner tests check the exit code for deny, inform, pass and malformed input, but only the JSON for ask, the pre-edit deny and the first stop block; the guard tests check verdicts, not process output. GitProbe’s git queries (unstaged changes, changed files) have no unit test, since GitProbeTests covers only worktree detection and file reads. The live refusal in criterion 8 exercised the unstaged-changes query against real git.
  7. Given a fresh Claude Code session, when a file under backend/ is read, then the loaded context lists backend/CLAUDE.md; likewise for frontend/. Observed by hand on 2026-11-04 in a fresh Claude Code desktop session on a worktree of main at 1177aba3; between that commit and 6b32bc2f only the 0019 card changed. Reading backend/src/Calendar.Api/Program.cs made Claude Code inject backend/CLAUDE.md and the backend/AGENTS.md it imports right after the read. Reading frontend/apps/web/src/queryClient.ts did the same for frontend/CLAUDE.md and frontend/AGENTS.md. An ls through Bash under frontend/ beforehand loaded nothing. Not automated.
  8. Given a worktree with an unstaged edit, when an agent runs git restore on that file through Claude Code, then the hook refuses with a reason; and an edit of contracts/openapi.json is refused the same way. Observed by hand in the same session. The session context opened with agent-hooks active (tools/agent-hooks, .NET runtime 10.0.14), and dotnet --version at the repo root was 10.0.403. With a throwaway line appended to README.md, git restore README.md through Bash was denied by the PreToolUse hook: “Unstaged changes in README.md would be discarded. Save the patch (git diff > file) or make a WIP commit first, then restore the saved version explicitly (AGENTS.md: preserve the fix when proving a regression test).” The probe was then removed with an edit. A one-character Edit of contracts/openapi.json (3.1.1 to 3.1.2) was denied: “openapi.json is generated. Run just contracts for the API contract and TS client, dotnet restore for packages.lock.json, or pnpm install for pnpm-lock.yaml, and commit the result instead of editing it.” Neither probe was committed. The ask guard was not run live, because it prompts the user; Shared_database_from_a_linked_worktree_asks and the #222 smoke test cover it.
  9. Given the change is complete, when I run just check, then it passes. just check passed locally on the head of the close-out PR (#229), with Podman serving the Docker socket for the Testcontainers suites; the PR description names the revision and the CI result. Each delivery PR passed CI on its final head, and CI passed on main at 6b32bc2f.

Design decisions

Any Decision Records

ADRDecisionWhy it matters for this story
0017Repo tooling is .NET file-based apps with analyzers and tests per folderThe hooks tool follows this layout and is discovered by just tools test; it uses #:include, so it needs SDK 10.0.300 and degrades to prose-only rules on older SDKs.
0042Layer agent guidance by scope (root, nested AGENTS.md with CLAUDE.md shims, skills, folder READMEs) and enforce its invariants with Claude Code hooks built as repo toolsSets where each kind of guidance lives, the deny/ask/inform policy, the (hook) line that keeps every enforced rule in prose for other agents, and the fallback to prose when the tool cannot run. Drafted with adr-draft, approved in review and set to accepted in #222 before it merged; the CALM model lists it in metadata.adrs.

Other decisions (not ADR-worthy)

  • Nested AGENTS.md plus a CLAUDE.md shim, not .claude/rules: path-scoped rules are Claude-only, while nested AGENTS.md is read natively by Codex and Cursor. The shim exists because nested AGENTS.md under a root CLAUDE.md is undocumented for Claude Code.
  • The shared-database guard asks instead of denying: a maintainer in a worktree may want the shared database; the prompt names the isolated stack from the run-calendar skill as the alternative. Confirmed in review on #222.
  • The issue-handover skill stays model-invocable: the old section applied to “its individual behaviours” too, so a prose request such as “watch PR N for review comments” must still load it. The description is scoped to explicit requests.
  • No (hook) markers before the hooks exist: the hooks PR preceded the root rewrite, so the rewritten rules point at hooks that were already in place.
  • tools/README.md instead of a repo-tooling skill: about thirty lines of gotchas that people also read, with precedent in tools/infra/README.md.

  • Not tested: no test proves that agents follow prose, so the root, the nested files and the skill are reviewed by hand. The line and word budgets are not enforced. The if filters in .claude/settings.json have no test; criterion 8 observed the git and openapi.json filters firing live.

Review changes during delivery

  • Stash guard dropped: #222 first denied bare git stash. Review dropped it, with its 12 test cases, because it is a harness rule rather than repository guidance. The root lost the stash line too.
  • An if filter on every handler: each handler in .claude/settings.json carries a permission-rule filter (Bash(git *), Bash(gh *), Bash(just *), Bash(docker *), and since #376 Bash(env *), Bash(sudo *), Bash(command *), Bash(builtin *) and Bash(exec *), one per generated path, Edit(**/*.cs)), one handler per pattern, so an unrelated command or edit starts no process. The filter is best effort: when Claude Code cannot tell which commands a Bash input runs, the hook runs and decides in process.
  • Code and tests split by cohesion: one file per guard or check, HookProtocol.cs for the hook JSON and IRepoProbe.cs for the repository questions, one test class per file included by agent-hooks.tests.cs. The same 63 tests passed before and after the split.

Lessons learned, known issues and follow-ups

  • Measured: root AGENTS.md 148 lines / 4,249 words before, 51 / 1,367 after (wc -lw). A cached hook call took 0.23–0.29 s during delivery, with a first compile of about 5 s; on 2026-11-04, five cached pre-bash calls on main content took 0.265–0.291 s each (piped sample input, timed with date, on the development machine under WSL). Later that day, at a load average of about 2.4, the same call took 0.50–0.66 s, so the cost depends on machine load.

  • A review suggestion committed after a squash merge misses main: the suggestion on #221 was committed to its branch after #221 had merged, so it reached main only through #226 from fresh main. This is the case that “Verify delivery across a merge” in AGENTS.md describes (#180/#186), met again: re-read the PR state before adding to a reviewed branch.

  • Remote rebases leave local branches stale: the stacked branches were rebased and retargeted on GitHub as their bases merged. Fetch and rebuild the local branch from the remote before pushing. Force-push is blocked by the auto-mode classifier, so the way out of a rejected push is to rebuild on the fetched branch, not to force it.

  • Hooks load at session start: the session that builds or changes them can’t observe them live. Plan a fresh-session check, as criteria 7 and 8 did.

  • Nested guidance loads on Read or Edit only: Claude Code injects backend/ or frontend/ guidance when its own Read or Edit tool touches a file there. A Bash ls did not trigger it, so an agent that explores only through the shell may miss the area practice until it reads a file.

  • The SessionStart line named only the runtime: it showed Environment.Version (10.0.14 in the live check), while the minimum that matters is SDK 10.0.300 (10.0.403 here), so the figure read as too old. The tool’s header comment and parameter name said SDK. Fixed after close-out by #233 (#231): the line now names both (.NET SDK 10.0.403, runtime 10.0.14), which keeps ADR-0042’s “names the runtime” true. It costs about 0.3 s once a session, for dotnet --version.

  • The public-post guard did not read gh api bodies: it scanned only the words of a gh api post, never the file or heredoc that --input or a typed field’s @ value (-F body=@file) sends. A post made that way skipped the check. Found while delivering #321 and fixed after close-out by #373 (#369): the guard reads those sources as it reads --body-file, and no longer scans the local path of a source it can read. The security and performance reviews of that PR found four defects in the change, recorded on #369 and fixed in the same PR:

    • the hook read any file whole, which took 16.4 s for 50 MB;
    • it denied a binary upload on its bytes;
    • it dropped the words naming a source it could not read, where main scanned them;
    • it took an option-like word as a source path.

    GitProbe.ReadFile now reads only a regular text file of at most 1 MiB. A source it cannot read is scanned by the words that name it. Since #374, delivered in #377, a source is read through what the command states: its assignments and ~ expand, a file an earlier heredoc, echo or printf writes is read, and so are a < file redirect and what a command pipes in. Known gap: a variable set in an earlier shell call, or a $(...) path, still leaves only the words to scan.

  • A prefix or wrapper hid the command from every Bash guard: each guard was chosen by a segment’s first word, so FOO=1 gh …, env git … or sudo git … skipped all of them. Found by the security review of #377 and fixed by #381 (#376): ShellCommand.Split unwraps assignments, env, command, builtin, exec, nohup, time, nice, timeout and sudo, and reduces a path to the command to its name. Claude Code’s if filters strip leading assignments and some of those wrappers but are not documented to strip env or sudo, so those two got handlers of their own, and so did command, builtin and exec, since the hook docs do not say the filters apply that list. A path such as /usr/bin/gh is not documented either. The security review of the fix found five more defects, recorded on #376 and fixed in the same PR: sudo -D (not -C) changes the directory; an assignment builtin behind a wrapper that leaves the shell (sudo export …) is not recorded; bundled and attached short options are read as the wrapper reads them; builtin cd moves later segments; and command, builtin and exec got handlers too. A command run as a string (bash -c, eval, xargs) is still not unwrapped.

  • Limits: the hooks are Claude Code only; other agents follow the (hook) lines by hand. Below SDK 10.0.300 the tool fails to compile, Claude Code treats that as a non-blocking error, and the rules stay prose (ADR-0042).

  • Follow-up: #228, delivered in #236, turned two code rules that frontend/AGENTS.md stated as prose into ESLint rules (frontend/eslint.config.js): no new QueryClient( outside createQueryClient, and no Intl.DateTimeFormat or toLocale*String outside features/agenda/dayTime.ts (the four toLocaleString calls moved onto a cached formatDateTime, and the one test that called new QueryClient( now uses createQueryClient). frontend/AGENTS.md marks them (lint). useNow() placement stays prose: no selector can judge “the smallest component”.

User guide

Working in the repository with an agent

Open a session anywhere in the repository and the agent reads a short guide that every session needs. When it reads or edits backend or frontend code, it also picks up that area’s practices; other agents such as Codex and Cursor read the same text natively. Ask for an issue-driven handover, or for one of its behaviours such as watching a pull request for review comments, and the agent loads that protocol.

In Claude Code, the session opens with a line saying the repository’s hooks are active and which .NET SDK and runtime they run on. From then on:

  • If the agent tries to discard unstaged changes with git restore or git checkout --, it is stopped and told to save the patch or make a work-in-progress commit first.
  • If it tries to post an issue, pull request or comment that contains a path on your machine or a private session handle, the post is stopped, naming what was found.
  • If it tries to hand-edit a generated file (the API contract, the generated client or a lock file), it is stopped and told which command regenerates the file.
  • If it runs a shared-database command from a separate worktree, you are asked to approve, with the isolated stack offered as the alternative.
  • After it edits a C# file with a line over 140 characters, it is told which lines to wrap. If it finishes a turn with the API changed but the contract not regenerated, it is asked to regenerate it once.

The hooks need .NET SDK 10.0.300 or later; just doctor checks the toolchain. With an older SDK they do nothing, and the same rules still apply as written guidance. Each rule the hooks enforce is also written in the root guide, marked (hook), so agents without hooks follow it by hand. Personal Claude Code settings that should stay out of git go in the git-ignored local settings file.
