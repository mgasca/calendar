# Infrastructure tooling

Use `make doctor ARGS=--infra` to check the pinned Azure CLI and Bicep. Local application development does not require them. Azure CLI uses its installed Bicep binary, never a binary found on PATH.

Set `AZURE_DEPLOYER_CLIENT_ID` to the target environment's deployment identity client ID. The tool resolves its object ID through Microsoft Graph, even when the operator is signed in as a user; this avoids granting the human operator the pipeline's vault role. The pipeline identity can read its own service principal without tenant-wide Graph permissions; a human caller needs permission to read that principal. `CALENDAR_CONTAINER_IMAGE` optionally overrides the parameter file's image.

First deploy the `foundation` phase, grant the owner Key Vault Secrets Officer on the ops vault, and run `make infra-secret-init ENV=staging`. Then deploy the `full` phase. The owner command refuses to overwrite an existing password; password rotation requires a coordinated manual change to PostgreSQL and the ops vault. The deploy identity needs Key Vault Secrets User on both vaults. Full preview requires the owner's secret initialization; foundation preview works before it.

Supply extra IPv4 addresses or CIDRs with repeatable `--allow-ip` through `ARGS` or comma-separated `AZURE_ALLOWED_IPS`; the tool converts CIDRs to PostgreSQL firewall ranges. CI can use the environment variable of the same name.

The tool creates mode 0600 temporary files for the password and deployment parameters and deletes them in a `finally` block. Azure CLI receives only the file path, never a secret value in an argument. Files are placed in a private mode 0700 directory under `XDG_RUNTIME_DIR`, or `~/.cache` when it is unavailable. Abrupt termination can leave files behind; startup removes files with the tool prefix older than 24 hours, and the owner can remove them sooner after ensuring no command is running. On an Azure CLI failure, the tool shows the current step, command path (without argument values), exit code, sanitized stdout/stderr and any available failed deployment operations. Output is limited to the last 60 lines / 8 KB; pass `ARGS="--verbose"` or set `INFRA_VERBOSE=1` for the full sanitized output. A full sanitized transcript is written to a mode 0600 file in the same private directory and its path is printed; inspect it before sharing. The next startup removes transcripts older than 24 hours.

Deployment, what-if and read-only Azure calls retry recognized transient failures twice by default, after 60 and 120 seconds. Use `ARGS="--retries 0"` or `INFRA_RETRIES=0` to disable retries; `--retries N` overrides the environment. Secret, role and firewall creation and other mutating calls are not automatically retried. SIGINT/SIGTERM cancel the wait and allow cleanup. Hints are diagnostic suggestions, not proof of the cause.

PRs lint and build the templates. Protected environment branch restrictions prevent PR branch OIDC authentication, so a workflow dispatch from `main` previews both environments; production still requires approval. Review each preview and investigate incomplete results. A no-change preview should show no resource changes; ARM incremental deployment does not delete resources removed from templates.
